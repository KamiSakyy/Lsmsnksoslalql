# FCMessenger ⚡

Мессенджер для Android, где **весь транспорт — только FCM data-сообщения**.
Текст уже лежит внутри пуша, получателю ничего докачивать не надо —
поэтому сообщения долетают, **даже когда на балансе 0 ₽ / 0 МБ**,
пока жив push-канал Google (а он у операторов обычно живёт дольше всего).

Плюс шифрование как в Signal: сервер видит только шифротекст.

## Как это работает

```
Ты (0 ₽)                    Google                      Друг (0 ₽)
  │                           │                            │
  │── 1. HTTPS ~1КБ ──▶ Cloud Function                     │
  │   {to, шифротекст}        │                            │
  │                           │── 2. FCM data-push ──▶  📲  │
  │                           │   {from, шифротекст}    расшифровка,
  │                           │                        уведомление
```

- **Отправка** — один крошечный запрос на серверы Google (Function находит свежий
  FCM-токен друга и шлёт пуш с высоким приоритетом).
- **Приём** — пуш с текстом внутри → расшифровка на устройстве → уведомление.
  Никаких «докачек с сервера» — в этом весь фокус 0-баланса.
- **Шифрование** — Tink ECIES (P-256 + HKDF + AES-GCM). Приватный ключ в Android
  Keystore, наружу не уходит. Сервер прочитать переписку не может.
- **Статусы** — ✓ отправлено, ✓✓ доставлено, синие ✓✓ прочитано (ack/read тоже
  едут через FCM).
- **«Печатает…»** — тоже FCM.
- **0-режим** (тумблер «0» в шапке чатов) — отправка только по локальному кешу
  ключей, вообще без лишних запросов.
- **Очередь** — нет сети совсем → сообщение ждёт и улетает само (WorkManager).

> Честная оговорка: 100% гарантии «при любом операторе» не даст никто — это
> зависит от того, как оператор душит трафик при нуле. Но архитектура выжимает
> максимум: весь трафик — только Google, минимум байт, ничего лишнего.

## Что внутри

- `app/` — Android-приложение (Kotlin, Jetpack Compose + Material3, Room,
  DataStore, WorkManager, Tink, Firebase Auth/Firestore/Functions/FCM)
- `functions/` — relay на Node.js 20 (одна функция `sendMessage`)
- `firestore.rules` — правила базы (справочник пользователей + ники)

## Запуск за 15 минут

### 1. Firebase-проект
1. [console.firebase.google.com](https://console.firebase.google.com) → Add project.
2. **Authentication** → Sign-in method → включить **Anonymous**.
3. **Firestore Database** → Create database (production mode, регион поближе).
4. **Cloud Messaging** — работает из коробки.
5. Project Settings → **Add app → Android**, package `com.fcmessenger.app` →
   скачать **`google-services.json`** → положить в папку `app/`.

### 2. Сервер (relay + правила)
```bash
npm i -g firebase-tools
firebase login
firebase use --add            # выбери свой проект
cd functions && npm i && cd ..
firebase deploy --only firestore:rules,functions
```

### 3. Приложение
1. Открыть папку проекта в **Android Studio** (нужен JDK 17).
2. Дождаться Gradle Sync → **Run ▶** на телефоне.
3. Ввести имя + ник на двух телефонах → добавить друг друга по нику → писать.

### 4. Проверка «нулевого баланса»
1. Добавьте друг друга в контакты заранее (чтобы ключи закешировались).
2. Включите **0-режим** (тумблер в шапке).
3. У получателя: режим «0 МБ» (или дождаться реального нуля 😄).
4. Отправь сообщение — оно должно прийти пушем.

> Совет: убери приложение из оптимизации батареи
> (Настройки → Батарея → Без ограничений), чтобы пуши будили его стабильно.
