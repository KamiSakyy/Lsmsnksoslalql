# Noir P2P — Android Java

Чёрный Android P2P-чат на Java. Проект собирается с **Android SDK 36**, `targetSdk 36`, `minSdk 26`, Java 17 и актуальным Gradle 9.4.1 / Android Gradle Plugin 9.2.0.

## Что уже реализовано

- Анонимная авторизация Firebase через REST API; Firebase UID служит ID, которым собеседники обмениваются вручную.
- Firebase Realtime Database REST + SSE используется для WebRTC offer/answer, ICE-кандидатов и приглашений.
- Текст и файлы идут напрямую между устройствами через зашифрованный WebRTC DataChannel (DTLS/SCTP); содержимое переписки в Firebase не записывается.
- Фото, видео, аудио/музыка, документы, голосовые заметки и запись короткого видео-сообщения («кружка»); ограничение вложения — 50 МБ.
- Локальная история SQLite, очередь исходящих сообщений при временном отсутствии P2P-канала, переподключение с задержкой.
- Постоянное уведомление foreground-сервиса типа `remoteMessaging`; уведомления о сообщениях и приглашениях.
- Тёмный интерфейс, Android Photo/Document Picker и системный выбор приложения для открытия медиа.

## Включить Firebase перед запуском

Проект использует переданную конфигурацию Firebase (`meow-874ce`). В Firebase Console нужно:

1. В **Authentication → Sign-in method** включить **Anonymous**.
2. Убедиться, что создана Realtime Database в регионе `europe-west1`.
3. Применить правила из `firebase/database.rules.json`:
   - Firebase CLI: `firebase login`, затем из корня проекта `firebase deploy --only database`;
   - или скопировать JSON в раздел **Realtime Database → Rules** и нажать **Publish**.

Без включённой анонимной авторизации приложение не сможет создать UID; без правил RTDB запросы будут отклонены. API key клиента не является секретом доступа к базе: безопасность обеспечивается Firebase Authentication и RTDB rules. Не заменяйте правила на открытый `.read/.write: true`.

## Как связать два устройства

1. Установите APK на оба устройства и запустите приложение.
2. Скопируйте свой UID на главном экране и передайте его собеседнику любым удобным способом.
3. Каждый добавляет UID второго через **Новый чат**. Если приходит неизвестное приглашение, его можно принять на главном экране.
4. Для установки WebRTC-канала приложение собеседника должно быть открыто или работать в разрешённом Android foreground-режиме. После подключения текст и вложения передаются напрямую.

UID анонимного Firebase-пользователя хранится на устройстве. Очистка данных приложения или переустановка создаёт новый UID; старый ID после этого использовать нельзя.

## TURN для работы через сложный NAT

В проекте по умолчанию есть публичные STUN-адреса. Одного STUN недостаточно для всех мобильных сетей, CGNAT, корпоративных Wi‑Fi и симметричного NAT. Для максимально надёжного соединения настройте собственный TURN-сервис (например, coturn или управляемый TURN) и задайте:

- `TURN_URLS` — список URL через запятую, например `turns:turn.example.net:5349?transport=tcp,turn:turn.example.net:3478?transport=udp`;
- `TURN_USERNAME`;
- `TURN_CREDENTIAL`.

В GitHub добавьте эти значения как **Actions secrets** с теми же именами. Workflow передаёт их в Gradle BuildConfig. Не коммитьте TURN-пароль в исходники. Без рабочего TURN в некоторых сетях P2P соединение физически невозможно установить.

## Сборка и получение файлов через GitHub Actions

Сборка APK намеренно выполняется **в GitHub Actions**, а не в локальной среде агента. Workflow находится в `.github/workflows/android.yml` и запускается при push в `main`/рабочую ветку, для PR в `main` или вручную через **Actions → Android APK и handoff → Run workflow**.

После успешного запуска:

- в папке `handoff/` этой рабочей ветки появятся актуальные `NoirP2P-debug.apk` и `NoirP2P-source.zip` — workflow добавляет отдельный CI-коммит;
- ту же пару можно скачать из **Artifacts → NoirP2P-handoff** у этого запуска (артефакт хранится 30 дней).

ZIP исходников собирается из tracked-файлов и не включает предыдущие APK/ZIP. Debug APK не предназначен для публикации в Google Play — для релиза нужна отдельная release-подпись. Если GitHub не разрешает CI-коммит в `handoff/`, включите для репозитория **Settings → Actions → General → Workflow permissions → Read and write permissions**. APK по-прежнему можно скачать из Actions Artifacts.

## Ограничения, важные для реального использования

- Android не позволяет гарантировать вечную фоновую работу: пользователь может остановить приложение, система — ограничить сеть/сервис, а производитель — агрессивно выгружать процессы. Foreground service с уведомлением и повторы улучшают стабильность, но не заменяют push.
- Сейчас входящий сигналинг слушается Realtime Database SSE foreground-сервисом. Если процесс полностью остановлен системой, мгновенное пробуждение чата требует отдельной настройки Firebase Cloud Messaging (FCM); в данном исходном проекте FCM не подключён.
- Для гарантированной связи между разными типами NAT нужен надёжный TURN relay. Файлы передаются P2P и не имеют серверной доставки/резервной копии: оба клиента должны быть доступны для установления DataChannel.
- WebRTC защищает установленный DataChannel транспортным DTLS-шифрованием. Отдельное приложение-уровневое E2EE с проверкой ключей/QR-кодом здесь не реализовано.
- Видео-кружок создаётся системной камерой как короткий видеоролик и отправляется как вложение; это не live-видео звонок.
